# AgentForge V1.8 — External LLM Live Mode

V1.8 replaces the in-CI fake OpenAI-compatible endpoint with a real external provider when repository configuration is present, while preserving the V1.0–V1.7 safety boundary.

## Repository configuration

Add these under GitHub repository **Settings → Secrets and variables → Actions**.

Variables:
- `AGENTFORGE_LLM_BASE_URL` — OpenAI-compatible API base, for example `https://provider.example/v1`
- `AGENTFORGE_LLM_MODEL` — provider model id
- optional `AGENTFORGE_LLM_ALLOW_ANONYMOUS=true` only for an explicitly anonymous HTTPS endpoint

Secret:
- `AGENTFORGE_LLM_API_KEY` — provider API key. Never commit it to the repository.

The external workflow never prints the key. Remote plain-HTTP endpoints are rejected; HTTP is accepted only for localhost/127.0.0.1 test servers.

## Connectivity test

```bash
agentforge model-check
```

Expected result is strict JSON containing `probe.ok=true`. The command also prints only a redacted configuration summary.

## Live planning

```bash
agentforge plan "给商城增加优惠券功能" --req-id REQ-980001 --adr-id ADR-980001
```

## Autonomous live development

A target repository must provide `.agent/execution-profiles.yaml`. Verification commands are controlled by this file, not by the LLM.

```bash
agentforge autonomous-live "给商城增加优惠券功能" \
  --repo-root . \
  --profiles .agent/execution-profiles.yaml \
  --base main \
  --req-id REQ-980001 \
  --adr-id ADR-980001
```

After local verification, explicit push/PR can be enabled:

```bash
agentforge autonomous-live "给商城增加优惠券功能" \
  --repo-root . \
  --base main \
  --push \
  --create-pr \
  --github-repo owner/repository
```

For PR creation set `AGENTFORGE_GITHUB_TOKEN` or `GITHUB_TOKEN`. The GitHub token is used only by Git/PR publishing and is never placed into the LLM prompt.

## Execution profile example

```yaml
allowed_verification_executables:
  - mysql
  - redis-cli
  - mvn
  - node
  - npm

agents:
  database:
    context_paths:
      - database
      - .agent
    verification:
      - argv: [mysql, --version]
        cwd: .

  backend:
    context_paths:
      - server
      - .agent
    verification:
      - argv: [mvn, test, -q]
        cwd: server

  miniapp:
    context_paths:
      - miniapp
      - .agent
    verification:
      - argv: [node, --test]
        cwd: miniapp

  admin:
    context_paths:
      - admin-web
      - .agent
    verification:
      - argv: [npm, run, build]
        cwd: admin-web
```

Shell interpreters such as bash/sh/cmd/powershell/pwsh are always rejected by the profile loader.

## GitHub Actions

`.github/workflows/agentforge-external-live.yml` runs automatically on the V1.8 branch and can also be launched manually after it reaches the default branch. When no provider configuration exists, it reports `SKIPPED_REAL_MODEL=true` instead of pretending that a real model was tested.

## Important boundary

V1.8 does not give the LLM shell, Git credentials, repository tokens, or direct file-system authority. The model returns structured data only. AgentForge validates that data, applies scope/evidence gates, executes only orchestrator-approved verification commands, and keeps merge as a human decision.
